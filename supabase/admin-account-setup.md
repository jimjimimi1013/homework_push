# 관리자 계정 설치/검증

운영 배포 승인 전에는 이 절차를 실행하지 않습니다.

1. `20260911000000_add_admin_password_reset.sql` 적용.
2. `homework-api`와 `push-api` 배포. 기존 인증 설정 유지.
3. 기존 일반 계정을 승격하지 않고 별도 관리자 계정 1개를 생성.
   이름은 운영자와 확인하고, 관리자 비밀번호는 `0000`이 아닌 별도 강한 비밀번호를 사용.
   비밀번호/해시는 Git이나 공개 프런트 코드에 기록하지 않습니다.
   신뢰된 DB 관리자 연결에서 아래 SQL을 바인딩 파라미터로 실행합니다.

```sql
insert into public.app_users (username, password_hash, role)
values ($1, extensions.crypt($2, extensions.gen_salt('bf')), 'admin');
```

공개 관리자 가입/승격 API는 추가하지 않습니다. 기존 회원가입은 항상 student를 생성합니다.
관리자는 기존 로그인 화면을 사용하며, 기존 선생님 화면의 계정 메뉴에만 `계정 관리`가 추가됩니다.
관리자 본인 비밀번호 변경/로그아웃도 기존 계정 메뉴를 사용합니다.

## 승인 후 별도 테스트 계정으로 확인할 항목

로컬 모의 테스트: `node --test scripts/test-admin-password-reset.mjs` (Node 24).
이 테스트는 UI 이벤트와 실제 API 소스의 권한 분기를 확인하며, DB에서 SQL을 실행하는 통합 테스트는 아닙니다.

- student/teacher가 `/admin/accounts`, `/admin/reset-password`를 호출하면 403.
- 세션 없이 호출하면 401, 만료/비활성 계정도 거부.
- anon/authenticated의 RPC 직접 호출은 실행 권한 없음.
- 관리자 확인창 취소 시 요청 없음. 초기화 실패 시 성공 안내 없음.
- 학생/선생님 각각 초기화 후 기존 비밀번호는 실패, `0000` 로그인 성공.
- 해당 대상의 기존 세션만 만료, 관리자와 다른 계정의 세션은 유지.
- 비활성 대상은 비밀번호만 초기화되고 재활성화되지 않음.
- 관리자/존재하지 않는 계정은 초기화 대상에서 제외.
- 관리자 홈/학생/과제/알림/공지 및 상세·피드백·Push는 기존 선생님 흐름 사용.

초기화 비밀번호 `0000`은 임시 복구용입니다. 사용자는 복구 후 기존 비밀번호 변경 메뉴에서 즉시 변경해야 합니다.
